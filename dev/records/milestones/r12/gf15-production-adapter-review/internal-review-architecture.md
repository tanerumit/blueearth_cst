  - id: architecture-1
    severity: major
    section: "D5–D7; validation plan, Identity/report"
    finding: "The new environment-identity contract does not specify an execution-time comparison of the actual numerical environment against the retained request. Existing stale-plan reconstruction reuses the request's environment rather than observing the executing environment."
    rationale: "current_metric_request observes stage_environment only while constructing a request. build_metric_plan passes request['metric_environment'] straight back to metric_request; both reduce_metric_plan and publish_metric_set rely on that reconstruction. Consequently a plan created in environment A can be reduced in environment B and published with A's metric_environment_sha256. D7's fixed lmoments3 source guards do not detect a changed NumPy/SciPy/native dependency when the guarded lmoments3 files remain identical. D5 explicitly rechecks packaged schema/source bindings and report digest, but neither D5 nor D7 defines the corresponding live execution-environment check. The existing environment tests change supplied descriptors or construct new requests; those are not a stale-environment execution test. The observable consequence is a ready candidate metric set whose identity records a different numerical environment from the one that produced its values, defeating the stated platform/parity and reproducibility boundary. This is a pre-existing freshness gap that the proposed production qualification relies on, not a claim that v2 introduced the underlying implementation defect."
    suggested_fix: "Within the existing metric_plan/adapter scope, define a single bounded metric-environment resolver, including D7's installed source hashes, and require the execution process to compare its observed descriptor with the retained request before reduction. Define the final publication freshness check and raise MetricPlanStale on mismatch without publishing a ready marker; creating a new request is the explicit route to a new identity. Keep retained-set reading independent of the installed environment. Add a discriminating test that builds a plan in environment A, keeps the request, code and report unchanged, changes the observed numerical environment to B while preserving the pinned lmoments3 source hashes, and attempts reduction/publication: it must refuse before fitting and leave no ready marker. A newly resolved B request must produce a distinct metric identity while upstream identities remain unchanged."

No new modeling stage or managed-root run is performed by this review; namespace claim and run-control conformance are not asserted.

The legacy/new validation dispatch is implementable without recomputing old declarations. Keeping `metric-set/1` while versioning the inner validation record is coherent with the explicitly one-way compatibility guarantee. Report verification from copied bytes, rather than the currently installed asset, preserves retained-read portability. The existing publication flow reduces all tables before payload writes and writes the sole marker last, providing a suitable integration point for the report and complete-set refusal contract.
