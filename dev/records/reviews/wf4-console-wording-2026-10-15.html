Decisions behind the wording

  • Separate operations. Simulation plus metrics prepares forcing and runs selected scenario IDs. Metrics-only consumes retained responses and has no generation, preparation, simulation, or log/benchmark gather producers. Public target aliases must not imply work absent from that graph.
  • Separate immutable records from selected exports. Simulation identity, native response inventory, metric request, and metric set have different roles. The current CSV export is a convenience view; refreshing it does not rerun simulation or overwrite an immutable metric set.
  • Use the right count. Scenario runs, batches, concurrent batches, Julia threads, metric declarations, expected result keys, and available estimates are distinct. Per-batch progress positions and scheduler job counters must not be presented as experiment-wide run counts.
  • Say what reuse proves. Verified staged output can be reused after an interrupted attempt. A completed simulation record follows stronger publication checks. A matching model fingerprint establishes identity, not hydrological fit or scientific adequacy.
  • Preserve coverage and failure reasons. Duplicate-location mappings remain visible warnings. A failed batch can continue to later runs while still returning failure. An immutable metric set being ready does not imply every requested estimate is finite or scientifically qualified.
  • Correct stale labels without changing controls. The disk warning still says WF3 even though it is used by WF4. Label the estimate and budget clearly; preserve every selected run and do not turn a console edit into a silent concurrency cap or a changed simulation window.
Coverage and limits

This emitter-based review follows scripts/simulate_system.py, simulate_system.smk, its simulation and metrics-only rule modules, experiment reservation, model identity, batched Wflow execution, response planning, metric planning, and shared completion/progress messages. No simulation or metric computation was run to prepare it. Alternatives are not one observed transcript.

New-detail cards mark proposed messages where current code is quiet, including collection/run context, simulation reuse, forcing completion, response publication, metric availability, and current-export refresh. Availability summaries need actual result-level counts and explicit denominators before implementation.

Rule bodies that only publish records can be quiet; their RUN/DONE rows still appear. Header-field and progress examples are schematic rather than captured byte-for-byte output.

Upstream HydroMT/Wflow messages, serialized artifact details, exception tracebacks, Snakemake dependency diagnostics, and the outer all-workflow runner are outside the editable wording inventory. The legacy project-consistency helper is separated because the current graph does not schedule it. Preserve native diagnostics and retained per-run records rather than replacing them with broad success claims.
