# Independent Linux GF15 parity verdict

**Verdict: ACCEPTED for source-qualified Linux estimator parity.** This qualifies `gf15-lmoments-c/1` in the tested linux-64 WSL2 environment against the frozen candidate and retained numerical controls. It does not establish accuracy on actual basin responses or a complete Linux workflow run.

The isolated Pixi environment uses Python 3.12.13, NumPy 2.4.6, SciPy 1.18.0, and the D7-pinned PyPI `lmoments3` 1.0.8 wheel. The observed `__init__.py` and `distr.py` SHA-256 digests in `quantile-results.json` match the production source guard. `environment-comparison.json` records the distinct Linux and Windows package closures and lock digests; equal versions are not being mistaken for equal native environments.

`parity-probe.py` compared production with the frozen candidate on 196 sample/probability combinations: 168 accepted, 28 refused, and zero mismatches. Its additional 84 invalid-probability refusal cases also had zero mismatches. The comparison covers bit patterns of numerical fields, acceptance and refusal, warning records, exception-refusal data, and both diagnostic count maps. A 1e-9 change to a published accepted estimate failed the comparator. These counts and the discriminating mutant are retained in `parity-results.json`.

Of 44 independent quantile controls, 41 reproduce the Windows reference bits. `population_.2`, `positive_tau_.2`, and `snap_tau_-.00002` each differ by one ULP (absolute error at most 4.44e-16); all 44 satisfy the unchanged readiness bound `1e-10 * max(1, |q|)`. The Linux-specific owning tests now apply that bound and require each of four quantile mutants to breach it. Windows retains its bit-exact assertions. Reported owning-test results are 86 passed and five expected platform skips on each platform; the Linux skips are Windows-only bit assertions, and the Windows skips are Linux-only tolerance assertions.

The matrix does not force an allowlisted library exception or injected warning. Those behaviors rely on the targeted owning tests and the prior Windows diagnostic review; this verdict does not infer them from the matrix. Candidate normalization's full intermediate array and production-only stage/source fields are likewise outside direct candidate equality. Source guarding and record structure are covered by owning tests. The remaining integration gate is to update the integration verdict and validation map with this bounded Linux result. No scientific reason to retain Windows-only estimator acceptance remains within this scope.
