> [!note] Overview
> **What** — Scope the blast radius of the R12 code-identity contract during
> ACTIVE DEVELOPMENT. Today an edit to a console banner invalidates a generated
> scenario collection, because the console tier and the generation helpers share
> one 5,768-line module.
> **Why** — Two WF3 regenerations plus two WF4 experiment rebuilds in a single
> session (~12 min each), for changes that cannot affect a single number.
> **Effort** — medium; the investigation below is done, the decision is not

## The cost, measured

Closing `t2609161645` and `t2609162114` on 2026-09-16 required editing
`blueearth_cst/shared/snake_utils.py` twice. Each edit invalidated the rapid
collection, so each cost a full WF3 regeneration AND a WF4 experiment rebuild:

| | WF3 | WF4 | total |
|---|---|---|---|
| after the `_id` suffix fix | 1:33 | 6:46 | ~8 min |
| after the `display_root` fix | 2:39 | 9:38 | ~12 min |

Both changes were **console formatting**. Neither can alter an artifact: they
decide what characters reach a terminal.

The second rebuild also re-stranded `experiments/experiment_rapid`, which had to
be deleted and regenerated by hand — so the true cost includes a manual cleanup
step and a decision point each time.

## The mechanism, precisely

**Not "the fingerprint hashes `blueearth_cst/`."** That framing — written into
the `t2609161645` LOG row on 2026-09-16 and corrected there — is too coarse and
points at the wrong fix.

`repository_code_inventory` (`experiment/content_identity.py`) walks a
TRANSITIVE STATIC-IMPORT CLOSURE from declared entry paths. For WF3 generation
those entries are declared in `generation_plan.py`, and the closure resolves to
**32 Python files**:

```
experiment 18 | shared 11 | climate_analysis 2 | __init__ 1
```

`shared/snake_utils.py` is in it. That is correct and desirable — the generation
path genuinely depends on it.

**But look at WHAT it depends on.** Every name the closure imports from
`snake_utils`:

```
index_width   log_row   run_and_tee   stress_test_grid
tee_to_log    water_year_start_number
```

Six names. Now the console tier, checked against the same closure:

```
install_console_style  0 closure modules
_ConsoleHandler        0
run_header             0
open_run_header        0
run_summary            0
target_banner          0
rule_banner            0
display_root           0
warn_row               0
```

**Zero.** Every one of those is imported by Snakefiles only, and Snakefiles are
not entry paths. The console tier is inside the fingerprint purely because it
shares a module with six helpers that belong there. `snake_utils.py` is 5,768
lines and is a genuine grab-bag: `stress_test_grid` (scientific, must be in the
identity) sits beside `_ConsoleHandler` (presentation, cannot matter).

So the blast radius is set by MODULE GRANULARITY, not by what can actually
affect a result.

## Options

1. **Split the Snakefile-only console tier out of `snake_utils`** into e.g.
   `shared/console_style.py`. Nothing in any closure imports those names, so the
   module leaves the fingerprint entirely and a banner edit stops invalidating
   anything. Narrow, mechanical, no contract weakened — the identity still
   covers every file that can change a number. **Recommended.**
   - Caveat: `log_row` must STAY in the closure. Generation modules call it, and
     it writes into rule logs. Only the handler/banner/header tier moves. So this
     does not buy immunity for every console change — a `log_row` edit still
     invalidates — but it covers the handler tier, which is where the volume of
     console work is.
   - Check `_RULE_NUMBERS`/`_RULE_SUMMARIES`/`_RUN_HEADER` module-global state
     does not get split across two modules.
2. **A dev-only opt-out** (env var) that skips the code inventory, for the rapid
   fixture only. Cheap to build, and dangerous in exactly the way the contract
   exists to prevent: a stale collection that LOOKS valid. Would need the
   resulting artifacts marked untrusted, which is most of the work of doing it
   properly. Not recommended without a strong marking story.
3. **Accept it and make regeneration cheap instead** — a smaller rapid fixture,
   or a `make refresh-fixture` that does the WF3 + delete-experiment + WF4
   sequence in one command. Does not reduce the count, only the friction and the
   manual decision point. Complementary to 1, not an alternative.
4. **Do nothing.** Defensible if package edits are about to slow down. The owner
   says the opposite: development is active.

## Watch for

- The identity contract is LOAD-BEARING and this must not weaken it. R12
  acceptance rests on a generated collection being reproducible from its
  recorded inputs. Any option that removes a file from the inventory must
  demonstrate that the file cannot influence an artifact — the zero-import
  evidence above is that demonstration for the handler tier, and it should be
  re-derived, not trusted, at implementation time.
- The same closure question applies to WF4's two inventories
  (`metric_plan.py` entry, `simulation_record.py` entry) — check whether they
  drag in the console tier too before assuming WF3 is the only caller.
- `tests/test_provenance.py` and the interchange-contract tier pin parts of this;
  read them before moving a name.

## What landed — option 1, `6a4caaa9`

`blueearth_cst/shared/console_style.py` now holds the Snakemake console handler,
the banners, the run header and summary, `warn_row`, `warn_if_project_dir_in_repo`
and the `RuleIdentity`/`RuleRegistry` pair. `snake_utils` drops 5,768 -> 4,346
lines. The seven Snakefiles import from the new module directly.

**No re-export shim.** A convenience `from ... console_style import rule_banner`
in `snake_utils` would pull the tier back into all three closures and silently
restore the whole cost, with nothing looking wrong in the output and no other
test failing. Two tests in `test_module_import_direction.py` pin it: one on the
import edge, one on closure membership itself, so a change to how entry paths
resolve cannot drag it back by another route.

### The acceptance test, measured

```
baseline provider_code        d360dd414f41392a
after the split               985b9e52696d26c5   changes ONCE, by design
after a console-only edit     985b9e52696d26c5   UNCHANGED
```

The one-time change is unavoidable: the inventory hashes whole FILES, so
removing 1,422 lines from `snake_utils` moves its sha256. Reading that as a
failure would be the easy mistake. The deliverable is the second line.

`console_style` is absent from all three closures (32, 33, 26 files), and each
still contains `snake_utils` -- checked so the first assertion cannot pass
because the closure broke.

### The win is real but PARTIAL — the honest number

The tee tier did not move and could not: `script:` modules call `log_row`
directly and rules write through the tee, so it is genuinely part of what
produces a rule's log and belongs in the fingerprint.

| | lines |
|---|---|
| moved out (handler, banners, header, summary) | ~1,422 |
| console-ish code that STAYS, reachable | ~1,099 |

So roughly half the console surface is now free to edit and half still costs a
regeneration. Both of the 2026-09-16 edits that prompted this fall on the free
side. A future `log_row` or tee change will still invalidate -- that is correct
behaviour, not a gap, and it is why this note does not claim the problem is
gone.

`rule_id` and `format_elapsed` also stay: the closure reaches them, and they are
stable.
