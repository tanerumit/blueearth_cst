Decisions behind the wording

  • Keep the technical IDs. Preserve model, scenario, member, rule IDs, and output paths. Make the surrounding sentence readable; filenames remain useful when a file was written.
  • Name the count. A combination means model × scenario × member. A combination–window pair is a separate coverage unit. Figure eligibility counts are not the same as figures already written.
  • Separate lookup from coverage. The start count uses catalog-resolved points. Composition later marks a point partial or unavailable when requested windows cannot be used. In the supplied example, 132 × 2 = 264 pairs; 261 succeed. The two affected combinations account for three missing pairs, consistent with 130 fully resolved combinations. The run record is still needed to establish all statuses.
  • Say what is skipped and why. Group identical figure reasons across windows. Keep per-member coverage warnings unless a replacement summary retains complete coverage and detail paths.
  • Avoid universal timing claims. The “~14× slower” remote-open estimate comes from one environment. Warn that the setting may slow remote reads and show the setting the operator can change.
  • Keep compact lifecycle rows. Retain RUN/DONE and elapsed durations. Add short action summaries to rule starts; avoid repeating long paths in completion rows.
Coverage and limits

This is an inventory of message families, not every possible substituted value. The source appendix below retains every direct log_row call in the WF2 projection modules, plus reviewed shared paths. Python exceptions, full tracebacks, arbitrary upstream HydroMT/xarray/GDAL records, Snakemake’s dependency diagnostics, and the all-workflow runner’s outer orchestration are outside the editable wording inventory. They are not evidence of a completed execution and should not be silently filtered.

  • Workflow header, rule starts/completions, target, success/failure summary
  • Reference clipping, short windows, legacy configuration, best-effort variables
  • Spatial delineation, locations, waterbodies, river-network warnings
  • Acquisition, cached slices, repaired units, pinning, grid/calendar handling
  • Basin averaging, cached series, shared progress and elapsed timer
  • Change factors, incomplete coverage, output tables, composition/provenance
  • Analysis-window diagnostics, skipped products, unavailable member windows
  • Rendering, per-folder figure bundles, run-record output paths

The analysis producer retains “Shifted” and “Joined” branches, but the current window constructor sets both flags to false. These are marked dormant, not represented as normal output. Log/benchmark gatherers write artifacts without their own console body rows; their RUN/DONE rows are the reviewed messages.
