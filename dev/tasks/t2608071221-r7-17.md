> [!note] Overview
> **What** — A full Linux pipeline run and the Docker image remain unverified.
> **Why** — CI installs the Linux Pixi environment and runs tests, but has no untracked project fixture or data access for a real workflow run. Linux scientific outputs and container behavior therefore have no end-to-end evidence.
> **Trigger** — A Linux runner can access the baseline inputs and CMIP6 slices through a mounted source or a validated staged bundle, with enough capacity for a full run.

## Current assessment (2026-09-28)

This is a multi-day platform and numerical-validation task once the data and
runner are available. Data access and any cross-platform numerical differences
are the main unknowns. It remains parked; no Linux baseline or Docker run was
performed during this assessment.

- The current entry point is `test_case/project_config_baseline_linux.yml`, a
  twin of the Windows baseline config. Its catalog points at
  `/mnt/p/wflow_global/hydromt`; decide and document the Linux data source before
  running. The older `config/project_config_model_test_linux.yml` spelling is
  obsolete.
- CI's ubuntu leg installs Pixi and runs the unit suite. It does not run
  `pixi run install`, the five-workflow pipeline, or baseline comparison because
  the required data and untracked project tree are absent.
- `Dockerfile` currently references missing `src/` and
  `run_stress_test.smk` paths and does not stage the current workflow tree. An
  image build should be treated as unverified until these references are
  repaired. `scripts/run_snake_docker.sh` assumes the `/mnt/p` mount and the
  Linux baseline config.
- Four Windows path-spelling assertions skip the ubuntu leg. Preserve those
  Windows cases and add Linux-native equivalents where they test meaningful
  behavior: `tests/test_snake_utils.py`'s three marked cases and
  `tests/test_plot_workflow_dag.py::test_absolute_project_dir_is_used_verbatim`.

When the trigger fires: establish a reproducible Linux data mount or staged
bundle; run the baseline config natively with retained WF1 discharge
(`--notemp`); compare outputs against the Windows manifest with the documented
comparators and investigate material differences; rebuild and run the Docker
image against the same inputs; record Linux-specific fingerprints separately
from the Windows baseline. Revisit the split Linux catalog only after the run
works; collapsing catalog paths is a separate design choice.
