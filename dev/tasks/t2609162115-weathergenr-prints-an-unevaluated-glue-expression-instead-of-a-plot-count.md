> [!note] Overview
> **What** — An UPSTREAM defect, recorded for visibility, not for action here.
> `weathergenr`'s evaluation stage prints its message template verbatim instead
> of the values it meant to interpolate.
> **Why** — One cosmetically broken line in every WF3 run's console and merged
> log. It misreports nothing else; no artifact and no number is affected.
> **Effort** — none in this repo

## The evidence

From a clean WF3 run on `project_config_rapid.yml`, 2026-09-16:

```
20:42:53 - eval - Generating diagnostic plots
20:42:53 - eval - Generated {format(length(plots): {out_dir}, big.mark = ',')} diagnostic plots.
20:42:53 - eval - Computing fit metrics for all realizations
```

The braces reach the console literally. The intended line is presumably
`Generated 17 diagnostic plots.` — the very next stage says
`Moving 17 figure(s) to <scenarios>/.../plots`, so the count itself is right and
only its rendering is broken. The template is also malformed independently of
the interpolation: the `format(` call is unclosed and `out_dir` has been spliced
into the middle of its arguments.

## Not ours to fix

The string lives in the INSTALLED `weathergenr` package
(`.pixi/envs/default/lib/R/library/weathergenr`), not in `blueearth_cst/`. It is
compiled into the lazy-load database, which is why grepping the source tree for
it finds nothing.

AGENTS.md § Hard Constraints: a genuine upstream bug is flagged upstream or
worked around in our own code, **never patched inside a vendored package**.
There is nothing to work around here — the line is cosmetic — so the correct
action is upstream or nothing.

## If someone picks this up

- Report it to `weathergenr`, against the evaluation/plotting function that
  emits the `eval` stage rows. Quote the line above; it is self-describing.
- Do NOT edit anything under `.pixi/`. It is regenerated by `pixi run install`
  and an edit there is lost on the next install and invisible to everyone else.
- A fix arrives here by version bump, not by patch.
